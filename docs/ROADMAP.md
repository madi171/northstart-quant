# 完整计划与 v0.1 的差距

## 本次已经写入的工程能力

- React / TypeScript 操作前端，FastAPI 后端，PostgreSQL Compose 部署，SQLite 本地开发路径。
- 人工标的池、启停、JSON 导入导出；策略源码查看、派生版本、审批、撤销批准。
- 受限 Python 解释器、单标的回测、费用滑点、同标的基准、报告与可复现脚本。
- Parquet 行情快照、新闻 JSON 接口；优先级数据源、消息聚合、模型独立提案混合。
- 演示模型与 OpenAI-compatible 模型驱动、密钥环境变量引用、端点白名单。
- 持久化任务、调度、心跳、超时、取消、重试、运行快照和来源追溯。
- 分币种、分数据环境模拟账户；订单意图、人工确认、再次风控与幂等成交。
- 研究模型只使用训练期行情和新闻，独立样本外评估，人工批准新版本。
- SSE 状态刷新、任务明细、收益曲线、指数观察、源配置、模型配置与风险设置页面。
- Docker Compose、使用说明、验收场景和未执行的自动化测试。

上述为代码交付状态，尚未经过运行验证。

## 下一阶段：完善研究与多资产能力

1. 完成依赖解析，生成锁文件，执行测试、构建和浏览器端到端联调，建立持续集成。
2. 将回测从单标的扩展到同账户多标的组合，支持现金流、换汇、汇率快照、组合基准与策略归因。
3. 引入真实市场交易日历、时区、公司行动、退市标的与时点标的池；避免未来函数和幸存者偏差。
4. 为具体供应商实现行情、新闻和指数驱动，包括授权、限流、增量更新、质量检测、时间戳和口径校验。
5. 允许调度配置多条策略/标的任务，按各交易所收盘与数据就绪事件触发，替换当前统一每日9点轮询。
6. 将大盘特征、新闻提取结果做成带可见时间的策略 SDK 输入；当前新闻只进入模型研究上下文，大盘仅展示，未进入日频策略函数。
7. 提供模型角色路由、相互评审、供应商 token 费用换算、月度预算、模型调用独立历史；当前只支持并行语义的独立提案，执行按模型顺序进行。
8. 建立完整滚动训练与样本外评估；当前是固定70/30分割和分段稳定性评估，不伪称完整 walk-forward 优化。

## 后续阶段：生产执行

1. 在用户选定券商并取得凭据后实现 BrokerAdapter，并保留实盘总开关关闭，先联调沙箱账户。
2. 实现订单提交前二次报价、确认价格约束、部分成交、拒单、撤单、断线重连、状态查询和账单对账。
3. 引入各市场真实税费、最小单位、结算、可卖限制与涨跌停规则；当前买入当日禁止卖出是统一保守模拟规则。
4. 实现持续盯市、完整日亏损口径、持仓限额与紧急停止下的明确撤单流程。当前账户估值在信号和成交时更新，并标注报价时间。
5. 任意 Python 扩展必须使用无宿主凭据的独立沙箱；模型修改整个系统应走代码评审、持续集成、人工合并及受控部署，不允许自我修改线上权限。
6. 引入数据库迁移、审计防篡改、密钥轮换、会话撤销、告警、离线恢复演练和供应商故障注入。

## 供应商未选定时的默认处理

不擅自注册账户、不代填真实凭据、不采购数据、不宣称已连接实时行情或券商。接口、配置校验和演示链路可继续开发；实际适配器与最终交易规则必须依据所选供应商联调结果完成。
